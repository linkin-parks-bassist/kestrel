Run python3 tools/effect_library.py from the superproject root to verify the current-image library. It builds the production host compiler and existing core-test executable once, compiles each .eff, renders a sample model and the actual dsp_core with filter_master/lut_master/delay_master, and compares every output sample exactly. The batch includes defaults and all min/max combinations of the listed controls. Reports and dry-left/wet-right WAVs go to /tmp/kestrel-effect-library unless --output selects another directory. The example-effects owner records the current descriptors, counts, measured costs and deployment evidence.

The numerical probe contains signed endpoints, small values, an impulse, a step and 100/1000/8000-Hz tones at 44100 Hz. Defaults render 44100 samples; corners render 8192. The runner checks selected default linear-filter responses, unity/polarity and clipping ceilings, records descriptor/program SHA-256, block count, peak and maximum cycles, and requires output within 2551 cycles per sample. Mix=0 must preserve samples exactly for GROWL, BASSRING and FLANGE.

For your own mono PCM16 44100-Hz recording, run python3 tools/effect_library.py --effect CUBEDRV --param drive=12 --input bass.wav --output /tmp/cubic-bass. Named overrides are checked against declared bounds and passed through the existing effect setter before compilation. David plays bass guitar exclusively: audition bass fundamentals, harmonics and playing transients rather than assuming guitar-range material. Numerical probes check execution; they are not representative playing.

tools/dsp_model.py consumes production programming bodies, not .eff syntax. It models signed MADD compensation/rounding/saturation, ABS/MIN/MAX/CLAMP, private-state 18-bit Chamberlin SVF with Q15 cutoff and separately formatted damping, built-in sine/tanh LUT reads, 256-word scratchpad reads/writes, allocated delay buffers with fixed/modulated reads, writes and startup gain, and static compiler-programmed polynomials. The renderer exercises full reset before programming; scratchpad values then persist across samples. Both LUT models use the actual 2048-word ROMs with bit-exact sequential interpolation. Only the final instruction may write c0. Unsupported commands/opcodes, allocated LUT handles, out-of-profile memory handles and uninitialized channel reads fail explicitly.

Run python3 tools/test_eff_state.py for exhaustive compiled LUT inputs and persistent-state regression. Each LUT matches all 65536 signed16 input codes, supplemented by sine quadrant/periodicity and tanh monotonicity/endpoints checks. The 4161-sample memory fixture is independently checked against a saturating half-decay/add recurrence and immediate read-after-write. Sharing ROM words means exact LUT agreement is not an independent analytic table oracle. Run python3 tools/test_eff_delay.py for eleven 4096-sample compiled delay cases (45,056 exact outputs), independent tap/startup/feedback checks, paired buffers and 3–11-clock RAM completion. The responder checks per-handle bounds and uses nonzero initial words; it does not simulate SDRAM hardware. Negative A clamps to zero and final taps clamp to 1..size−1 as David requires. Exact-zero/negative offsets and a literal zero base delay independently return the latest completed write; they do not wrap into a long delay. The model permits sixteen buffers below 2^19 words each, totaling at most 2^20. The Core delay owner governs semantics and distinguishes the verified source fix from the installed carrier image. Run python3 tools/test_eff_poly.py for compiled quadratic/constant resources and all 65,536 signed16 inputs. It checks encoded allocation/coefficient words and an independent truncated-power reference, including the signed16 squared endpoint wrap. Polynomial programming supports fields 0..17, at most sixteen handles, fewer than 128 coefficients and zero feedback. Live coefficient bank updates/commits remain unsupported in this renderer. CORE_TEST_BUILD selects the isolated core build used by both the shell and Python helpers. Focused readback/SVF scripts retain their separate coverage.

Run python3 tools/test_eff_flange.py for an exhaustive signed16 check of the shipped degree-seven sine polynomial (analytic error below 64 codes and near-zero wrap endpoints), followed by full-period nominal 0.1/0.3/3-Hz sweep checks, eight-second synthetic bass transients, dry identity and silence. It exposes the existing descriptor oscillator prefix via an ordinary final MOV, using the same compiler and core. Its fixed 128-sample tap check requires compensated DC gain within 1% of the independently calculated energy normalization and at least 40 dB rejection of an anti-phase square input relative to that compensated passband at feedback 0/0.65/0.85. The current polynomial shape passes all 65,536 codes with maximum sine error 23.642 codes, and the current three fixed-tap checks pass in /tmp/kestrel-flange-energy-comb with notch residuals 0/36/65 codes. The compensation changes output gain; the older sustained renders below do not verify the current weights. Earlier ROM-waveform sustained sweeps/bass/silence runs passed 2,669,520 exact sustained outputs in /tmp/kestrel-flange-audition/comparison.json, plus 49,152 independently checked comb samples. Nominal 0.1/0.3/3-Hz rates measure 0.105143/0.304914/2.996535 Hz; defaults and full-wet maximum feedback/depth/rate change the synthetic bass signal, Mix=0 is exact dry identity and silence stays zero. The library owner records current results and listening feedback. This does not establish continuous parameter updates or physical sound.

Deploy verified files with python3 tools/upload_effects.py --port PORT --verified REPORT_DIRECTORY --log NEW_LOG effects/NAME.EFF [...]. It requires matching descriptor hashes from default verification, checks current partner magic/mask, skips identical files, stages 96-byte chunks within the console line limit, publishes and compares complete SD readback. Differing destinations need explicit --replace; publication deletes the old FAT destination after staging. It does not alter presets or reload descriptors. Magic/build bits do not establish ROM initialization: the installed image's vendor build missed sine/tanh hex files despite valid mask 6. Core's build procedure owns the fixed staging and unflashed repaired image; polynomial FLANGE and BASSRING avoid that dependency. When using an existing UART console session, send each file command and wait for its result before the next command; flooding multiple lines can drop bytes. Require exact complete readback before reboot/discovery. The Interface UART owner governs commands. The helper waits until 12 seconds uptime because the console precedes SD/codec startup, and handles IDF cursor-position queries on one connection.

Run python3 tools/test_eff_bass_levels.py for independent useful-level checks on default BASSRING/WAH/VOWEL/FLANGE, plus VOWEL Mouth endpoints. It compares 529,200 actual-core outputs exactly, requires default RMS within ±3 dB on specified synthetic inputs and no clipping there, both expected ring sidebands above 4,000 codes, vowel difference from dry above 0.35 of input RMS and difference between Mouth endpoints above 0.5. These bounded checks do not guarantee equal perceived loudness or musical character for all playing.
