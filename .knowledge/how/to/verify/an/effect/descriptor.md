Run python3 tools/effect_library.py from the superproject root to verify the current-image library. It builds the production host compiler and existing core-test executable once, compiles each .eff, renders a sample model and the actual dsp_core with filter_master, and compares every output sample exactly. The batch includes default settings plus all min/max combinations of the listed controls. Reports and dry-left/wet-right WAVs go to /tmp/kestrel-effect-library unless --output selects another directory.

The probe includes signed endpoints, small values, an impulse, a step and 100/1000/8000-Hz tones at 44100 Hz. Defaults render 44100 samples; corners render 8192. The runner checks default linear-filter responses, unity/polarity and clipping ceilings, records effect/program SHA-256, block count, peak and maximum cycles, and requires output within 2551 cycles per sample. The current sixteen-effect batch passes 84 programs and 1262656 exact model/RTL sample comparisons. Default maximum costs range from 18 to 126 cycles/sample. Evidence: /tmp/kestrel-library-verification-final.log, /tmp/kestrel-library-inversion.log for the collision-free INVPHASE name, /tmp/kestrel-character-{wah,vowel,octfuzz,drive}.log, /tmp/kestrel-growl-verification.log and /tmp/kestrel-effect-library/results.json.

For your own mono PCM16 44100-Hz recording, run python3 tools/effect_library.py --effect CUBEDRV --param drive=12 --input guitar.wav --output /tmp/cubic-guitar. Named parameter overrides are checked against the batch's declared bounds; tools/compile_eff.c sends overrides through the existing effect setter before generating programming bytes.

tools/dsp_model.py consumes production programming bodies, not .eff syntax. It models signed MADD compensation/rounding/saturation, ABS/MIN/MAX/CLAMP and private-state 18-bit Chamberlin SVF with Q15 cutoff and separately formatted damping. It rejects unsupported commands/opcodes, resource-format instructions and uninitialized channel reads. The renderer requires only the final instruction to write c0.

Deploy verified files with python3 tools/upload_effects.py --port PORT --verified REPORT_DIRECTORY --log NEW_LOG effects/NAME.EFF [...]. It requires matching descriptor hashes from default verification, checks current partner magic/mask, skips identical files, stages 96-byte chunks within the console's line limit, publishes and compares exact SD readback. Differing destinations need explicit --replace; publication requires deleting the old FAT destination after staging. It does not alter presets or reload descriptors. The Interface UART owner governs file commands. The helper waits until 12 seconds of carrier uptime because console startup precedes SD/codec initialization; otherwise boot logs can interleave with hex dumps. It handles IDF cursor-position queries over one serial connection.

The current sixteen-effect batch is on the carrier SD with byte readback verified; its example-effects owner records startup UI discovery evidence. The example-effects owner owns exact contents, cleanup backup, physical evidence and David's listening feedback. Numerical verification is not sonic acceptance: audition representative playing and control sweeps, and assess whether the effect is perceptibly useful before describing it as approved. David rejected the first four additions as insufficiently interesting; the example owner distinguishes that feedback from the new unapproved cross-modulation experiment.

Coverage excludes resource-programmed polynomial, LUT, delay and scratchpad operations, SPI framing, enclosing controller/mixer, converters, dynamic parameter sweeps and listening approval. Existing focused scratchpad/SVF tests retain their separate coverage. This is an extensible arithmetic/SVF effect loop, not complete one-pipeline system verification. Model and RTL agreement does not alone establish intended sound, compiler semantic correctness for all expressions or board qualification. Authored public usage is effects/README.md; the shared verification specification owns requirements.
