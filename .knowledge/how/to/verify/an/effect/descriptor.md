Run python3 tools/effect_library.py from the superproject root to verify the current-image library. It builds the production host compiler and existing core-test executable once, compiles each .eff, renders a sample model and the actual dsp_core with filter_master/lut_master/delay_master, and compares every output sample exactly. The batch includes defaults and all min/max combinations of the listed controls. Reports and dry-left/wet-right WAVs go to /tmp/kestrel-effect-library unless --output selects another directory. The example-effects owner records the current descriptors, counts, measured costs and deployment evidence.

The numerical probe contains signed endpoints, small values, an impulse, a step and 100/1000/8000-Hz tones at 44100 Hz. Defaults render 44100 samples; corners render 8192. The runner checks selected default linear-filter responses, unity/polarity and clipping ceilings, records descriptor/program SHA-256, block count, peak and maximum cycles, and requires output within 2551 cycles per sample. Mix=0 must preserve samples exactly for GROWL, BASSRING and FLANGE.

For your own mono PCM16 44100-Hz recording, run python3 tools/effect_library.py --effect CUBEDRV --param drive=12 --input bass.wav --output /tmp/cubic-bass. Named overrides are checked against declared bounds and passed through the existing effect setter before compilation. David plays bass guitar exclusively: audition bass fundamentals, harmonics and playing transients rather than assuming guitar-range material. Numerical probes check execution; they are not representative playing.

tools/dsp_model.py consumes production programming bodies, not .eff syntax. It models signed MADD compensation/rounding/saturation, ABS/MIN/MAX/CLAMP, private-state 18-bit Chamberlin SVF with Q15 cutoff and separately formatted damping, built-in sine/tanh LUT reads, 256-word scratchpad reads/writes, and allocated delay buffers with fixed/modulated reads, writes and startup gain. The renderer exercises full reset before programming; scratchpad values then persist across samples. Both LUT models use the actual 2048-word ROMs with bit-exact sequential interpolation. Only the final instruction may write c0. Unsupported commands/opcodes, allocated LUT handles, out-of-profile memory handles and uninitialized channel reads fail explicitly.

Run python3 tools/test_eff_state.py for exhaustive compiled LUT inputs and persistent-state regression. Each LUT matches all 65536 signed16 input codes, supplemented by sine quadrant/periodicity and tanh monotonicity/endpoints checks. The 4161-sample memory fixture is independently checked against a saturating half-decay/add recurrence and immediate read-after-write. Sharing ROM words means exact LUT agreement is not an independent analytic table oracle. Run python3 tools/test_eff_delay.py for eight 4096-sample compiled delay cases (32768 exact outputs), independent tap/startup/feedback checks, paired buffers and 3–11-clock RAM completion. The responder checks per-handle memory bounds and uses nonzero initial words; it does not simulate SDRAM hardware. Negative A is clamped to zero as David requires, with independent fixed-tap checks for either sign of B. The remaining negative-B/final-offset defect is reproduced separately as an expected bounds failure, not passing audio coverage. The model profile permits sixteen buffers below 2^19 words each, totaling at most 2^20; negative offsets that address outside their buffer are rejected. The Core delay owner governs the selected negative-A clamp and remaining negative-final-offset question. Focused readback/SVF scripts retain their separate coverage.

Run python3 tools/test_eff_flange.py for full-period nominal 0.1/0.3/3-Hz sweep checks, eight-second synthetic bass transients, dry identity and silence. It exposes the existing descriptor oscillator prefix via an ordinary final MOV, using the same compiler and core. Its fixed 128-sample tap check requires unity DC and at least 40 dB rejection of an anti-phase square input at feedback 0/0.65/0.85. The fixed-tap checks and full slowest sweep pass; remaining sustained sweep/bass/silence execution is still pending. The library owner records current results and listening feedback. This does not establish continuous parameter updates or physical sound.

Deploy verified files with python3 tools/upload_effects.py --port PORT --verified REPORT_DIRECTORY --log NEW_LOG effects/NAME.EFF [...]. It requires matching descriptor hashes from default verification, checks current partner magic/mask, skips identical files, stages 96-byte chunks within the console line limit, publishes and compares complete SD readback. Differing destinations need explicit --replace; publication deletes the old FAT destination after staging. It does not alter presets or reload descriptors. The Interface UART owner governs commands. The helper waits until 12 seconds uptime because the console precedes SD/codec startup, and handles IDF cursor-position queries on one connection.

Numerical verification is not sonic acceptance: audition representative bass playing and control sweeps before describing an effect as approved. The example-effects owner records David's negative listening feedback on the initial additions and Cross Growl. Check independent intended behavior as well as model/RTL equality: sustained carriers and sidebands, dry identity, silence and state recurrence can expose errors shared by compiler/model/RTL.

Coverage still excludes resource-programmed polynomial and allocated LUTs, negative-offset delay correctness, SDRAM controller/arbiter/pin timing, SPI framing, enclosing controller/mixer, converters, dynamic parameter sweeps and physical listening approval. Model/RTL agreement does not establish all compiler semantics, intended sound or board qualification. Full one-pipeline system verification remains incomplete. Public usage is effects/README.md; the shared verification specification owns requirements.
